# ATLAS — AUTONOMOUS BUILD AND DEPLOYMENT MISSION

You are an autonomous senior software engineer, product
designer, knowledge architect, data engineer, and
learning-science specialist.

Your mission is to BUILD, DEPLOY, TEST, and CONTINUOUSLY
IMPROVE a complete Progressive Web App called ATLAS.

ATLAS is a personal, offline-first knowledge and
long-term memory training application.

This is an execution assignment.

Do not stop after planning.
Do not stop after creating mockups.
Do not stop after generating a project skeleton.

Build the actual product, deploy it, and continue
improving it through successive working releases.

You have authority to make sensible technical and
design decisions within the requirements below.

====================================================
0. FIRST ACTION — CLOUDFLARE AUTHENTICATION
====================================================

YOUR FIRST TASK IS TO ESTABLISH CLOUDFLARE ACCESS.

Before implementing the complete application:

1. Inspect the development environment.
2. Check the current Node.js and package manager versions.
3. Check whether Wrangler is installed.
4. Install or update Wrangler if necessary.
5. Check existing Cloudflare authentication.
6. If necessary, initiate interactive Cloudflare login.
7. Verify the account and deployment permissions.

Use current supported commands such as:

If running in an environment where browser OAuth
callbacks cannot work, investigate the supported

Follow the CURRENT Cloudflare documentation.

configuration.

Do not expose authentication tokens.

Do not commit credentials to the repository.

If interactive authentication is required, ask me
to complete the authentication step.

Once authenticated, continue automatically.

====================================================

ATLAS helps a person build substantial,
interconnected general knowledge over many years.

Its purpose is not simply to answer trivia questions.

Its purpose is to:

- Improve long-term factual memory
- Develop historical understanding
- Strengthen geographical knowledge
- Recognize influential people
- Understand cultural and scientific developments
- Remember important events and dates
- Connect knowledge across domains
- Develop broad intellectual foundations

The product should combine:

1. A curated knowledge library
2. A structured knowledge graph
3. A memory scheduling system
4. Interactive recall exercises
5. Contextual explanations
6. Personalized learning priorities
7. A learning progress model

KNOWLEDGE IS A NETWORK, NOT A QUESTION LIST.

However, remember that the core user experience
must consist of EXCELLENT MEMORY EXERCISES.

Do not overengineer the knowledge graph at the
expense of question quality or learning experience.

====================================================
11. RELEVANCE AND DIFFICULTY ENGINE
====================================================

Build independent models for:

A. Knowledge significance
B. Expected initial difficulty
C. Personal memory difficulty
D. Exercise-specific difficulty
E. Question quality

Do not confuse these measurements.

SIGNIFICANCE

Estimate the educational importance of a knowledge item.

Consider:

- Historical influence
- Cultural importance
- Global significance
- Connections to major events
- Foundational usefulness
- Relevance to selected interests

INITIAL DIFFICULTY

Use measurable candidate predictors such as:

- Expected public familiarity
- Historical distance
- Geographic or cultural familiarity
- Conceptual complexity
- Required prerequisite knowledge
- Answer specificity
- Retrieval format
- Availability of meaningful memory anchors

Do not assume these predictors have fixed
universal effects.

For example, older information is not automatically
harder to remember.

A highly connected concept may be easier to learn
because it has more memory cues.

Use an explainable heuristic initially.

Calibrate difficulty estimates using actual
learning performance.

PERSONAL MEMORY DIFFICULTY

Measure how well the user actually remembers
a specific retrieval target.

The user's performance should increasingly replace
generic difficulty assumptions.

QUESTION QUALITY

Evaluate exercises according to:

- Historical or educational significance
- Contextual usefulness
- Clarity
- Factual reliability
- Retrieval suitability
- Redundancy

Reject ambiguous or trivial questions.

A difficult question is not necessarily a valuable one.

13. GAMEPLAY MECHANICS
====================================================

Implement a reusable exercise engine.

The knowledge graph is the source of facts.

Exercise templates turn those facts into meaningful
memory challenges.

Prioritize the following mechanics.

1. FREE RECALL

Present a question without answer options.

Let the user attempt an answer.

Reveal the correct answer with context.

Allow self-assessment where appropriate.

2. RECOGNITION

Identify a person, object, place, artwork,
or historical event from images or clues.

3. CHRONOLOGICAL TIMELINE

Place events or people in chronological order.

Examples:

Arrange US presidents.

Place historical events relative to one another.

Identify which event happened first.

4. BEFORE AND AFTER

Recall predecessors, successors,
or chronological relationships.

5. KNOWLEDGE CONNECTIONS

Identify relationships between people,
events, places, and institutions.

Example:

Which World War II military commander later
became US president?

6. MAP IDENTIFICATION

Recognize a country or county by its outline.

7. MAP LOCATION

Tap the correct country or region on an
unlabeled map.

8. ART RECOGNITION

Identify artists, paintings, and movements.

9. COLLECTION RECALL

Reconstruct meaningful knowledge sets.

Examples:

Name US presidents in chronological order.

Recall European capitals.

Name Nobel laureates in a selected category.

10. CONTEXT RECONSTRUCTION

Start with an entity and recall important
historical or conceptual connections.

For example:

Eisenhower
    -> World War II
    -> Allied command
    -> D-Day
    -> US presidency
    -> Cold War

The system must provide corrective feedback.

Prefer independently recalled answers over
multiple-choice recognition when appropriate.

Provide hints when useful.

Do not fabricate unsupported explanations.

====================================================
17. BACKGROUND KNOWLEDGE UPDATES
====================================================

Implement a robust, nonblocking knowledge update system.

The application should periodically check whether
new or improved knowledge packages are available.

DEFAULT TARGET:

Approximately once per day.

The update mechanism must be designed around
actual browser capabilities.

CRITICAL REQUIREMENT:

Do not assume a closed PWA can reliably execute
scheduled background tasks on iOS or Android.

Implement a reliable fallback.

CLIENT-SIDE UPDATE STRATEGY

When the application is active:

1. Check whether the last update check was more
   than approximately 24 hours ago.

2. If online, request a lightweight knowledge
   manifest from Cloudflare.

3. Compare available versions with locally
   installed knowledge packages.

4. Identify relevant updates.

5. Download suitable updates without blocking
   the learning experience.

6. Validate package integrity and compatibility.

7. Import new data into IndexedDB.

8. Atomically activate validated updates.

9. Preserve all existing learning progress.

10. Record update results in the developer log.

Checks should also run opportunistically:

- On application startup
- When returning to the application
- When network connectivity returns
- During long active sessions when appropriate

Throttle requests to avoid unnecessary network traffic.

Perform large parsing and validation operations
off the main UI thread when practical.

Use Web Workers for CPU-intensive processing.

Do not cause interface freezes during updates.

PERIODIC BACKGROUND SYNC

Investigate browser support.

Use it only as an optional enhancement.

Do not depend on it for correctness.

SERVER-SIDE UPDATE CHECKS

Investigate Cloudflare Workers Cron Triggers
for scheduled public knowledge update checks.

These may run even when the phone is offline
or the PWA is closed.

However:

Cloudflare must never need to store the user's
personal learning progress.

Server-side jobs may process PUBLIC knowledge
and prepare updated knowledge packages.

Use durable publication of versioned packages
when required.

Prefer the simplest approach that is reliable
and compatible with the project constraints.

Do not introduce a hosted database merely
to store user information.

If durable public package storage is needed,
use the smallest suitable Cloudflare-supported
mechanism and document its purpose.

Keep it separate from all personal learning data.

IMPORTANT:

An update check must not automatically introduce
a large volume of new educational content.

Distinguish between:

A. Corrections to existing knowledge
B. Updates to existing collections
C. Optional new topic expansions

Corrections can be installed automatically after
validation.

New topic expansions should generally be controlled
through the user's focus preferences.
